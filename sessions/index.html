Change a schema

Always on the home page

Know exactly what your migration will do before it touches the database. The plan is the review surface; drift is the proof.

sh · ptah-quick-start 

        
# Write the database's own schema into a file.$ ptah db read --db-url sqlite://app.db | tee schema.sqlCREATE TABLE "users" (  "id" INTEGER PRIMARY KEY,  "email" TEXT NOT NULL); # Drift compares that file with the database it came from.$ ptah schema drift --schema-file schema.sql \    --db-url sqlite://app.dbNo schema drift detected. # Now ask for a column, by rewriting the schema you want.$ cat > schema.sql <<'SQL'CREATE TABLE "users" (  "id" INTEGER PRIMARY KEY,  "email" TEXT NOT NULL,  "created_at" TEXT);SQL # The same check now has something to report.$ ptah schema drift --schema-file schema.sql \    --db-url sqlite://app.dbSchema drift detected (highest severity: warning).Failure threshold: all. Failing: true.Database: sqlite://app.db Findings:- columns_added: 1 (warning) # Ask what it would take to close it. A dry run executes nothing.$ ptah schema apply --schema-file schema.sql \    --db-url sqlite://app.db --dry-runPlanned schema changes:ALTER TABLE "users" ADD COLUMN "created_at" TEXT; # Run the reviewed plan. --auto-approve suits a disposable file.$ ptah schema apply --schema-file schema.sql \    --db-url sqlite://app.db --auto-approvePlanned schema changes:ALTER TABLE "users" ADD COLUMN "created_at" TEXT;Auto-approval enabled; applying schema changes.Schema apply completed successfully. # And the same check, a third time.$ ptah schema drift --schema-file schema.sql \    --db-url sqlite://app.dbNo schema drift detected.

        

      

    


    

      

        
Migrate embeddings

        Always on the home page
      

      
A new embedding model is built and checked beside the one being served. Queries keep reading the old vectors until an approved cutover moves them.


      

        

          sh · ptah-inference
          
        
          
          
          
          
        
        

        

        
# A new embedding model. Plan measures what it would take.$ ptah inference plansource.estimated_rows = 3 (measured)target.capability.vector_type = true (measured)[backfill] embed 3 in-scope source rowsConsistency mode: outbox # Build the new generation beside the one being served.$ ptah inference prepareprepared run quick-start for generation b7cc9eb5c7d2  - snapshot boundary: 753$ ptah inference backfill --batch-rows 10backfill finished: 3 scanned, 3 embedded, 0 skipped # Rows that changed while it ran are caught up, then indexed.$ ptah inference catchup --batch-rows 10caught up to transaction 761: 0 changed rows, 0 tombstoned$ ptah inference indexgeneration b7cc9eb5c7d2 has a valid index # Check it before anything reads it.$ ptah inference verify3 source rows, 3 target rowsevery deterministic layer passed # Queries still read the old vectors. Cutover is its own approved step.

        

      

    


    

      

        
Stop an unsafe one

        
      

      
A migration that would delete data is refused before it runs, with the reason and the safer order. Exit code 1 fails the build.


      

        

          sh · ptah-ci
          
        
          
          
          
          
        
        

        

        
# A pull request adds this migration.$ cat migrations/1700000100_drop_email.up.sqlALTER TABLE "users" DROP COLUMN "email"; # Check it before it reaches a database.$ ptah migrations lint --dir ./migrations \    --dialect postgresmigrations/1700000100_drop_email.up.sql:1 [warning] BC104: dropping a column retires a name application versions already deployed against the old schema still select and insert, so each of them starts failing the moment this migration commits, whether or not the column held any rows; deploy readers that no longer use the column first, then drop it in a later release (dropped column breaks deployed code)migrations/1700000100_drop_email.up.sql:1 [error] DS102: DROP COLUMN permanently deletes the column's data; deploy readers that no longer use the column first, then drop it in a later release (column dropped) 2 finding(s).warning: DS110P ran without the baseline schema it reads, so this analysis is thinner than the same directory would get against a dev database the run can read # The exit code is what fails the build.$ echo $?1

        

      

    


    

      

        
Go structs to SQL

        
      

      
The schema is annotated Go, and one file renders for each engine in the terms that engine has: PostgreSQL gets a real enum type, SQLite the CHECK constraint that means the same thing.


      

        

          sh · ptah-entities
          
        
          
          
          
          
        
        

        

        
# The schema is a Go struct. The annotations are the declaration.$ cat entities/user.gopackage entities //ptah:schema:table name="users"type User struct {	//ptah:schema:field name="id" type="SERIAL" primary="true"	ID int64	//ptah:schema:field name="email" type="VARCHAR(255)" not_null="true"	Email string	//ptah:schema:field name="plan" type="ENUM" enum="free,team,enterprise"	Plan string} # Render it for PostgreSQL.$ ptah schema render --root-dir . --dialect postgres-- Statement 1/2CREATE TYPE "enum_user_plan" AS ENUM ('free', 'team', 'enterprise'); -- Statement 2/2-- POSTGRES TABLE: users --CREATE TABLE "users" (  "id" SERIAL PRIMARY KEY NOT NULL,  "email" VARCHAR(255) NOT NULL,  "plan" enum_user_plan); # The same file, one flag apart.$ ptah schema render --root-dir . --dialect sqlite-- Statement 1/1CREATE TABLE "users" (  "id" INTEGER PRIMARY KEY,  "email" TEXT NOT NULL,  "plan" TEXT CHECK (plan IN ('free', 'team', 'enterprise'))); # No enum type in SQLite, so it is a CHECK. Nothing was dropped.

Adopt a database

        
      

      
A database that predates any declaration becomes annotated Go, constraint names and referential actions included.


      

        

          sh · ptah-adopt
          
        
          
          
          
          
        
        

        

        
# A database nobody ever wrote a schema file for.$ ptah introspect --db-url sqlite://app.db --out ./modelsGenerated 2 Go file(s) in /tmp/app/modelsImported 2 table(s), 5 field(s), 0 enum(s) # What it wrote is the annotated Go you would have written.$ cat models/posts.go// Code generated by ptah introspect; DO NOT EDIT. package models //ptah:schema:table name="posts"type Posts struct {	//ptah:schema:field name="id" type="INTEGER" primary="true"	Id *int	//ptah:schema:field name="user_id" type="INT" not_null="true" foreign="users(id)" foreign_key_name="fk_posts_user_id" on_delete="NO ACTION" on_update="NO ACTION"	UserId int	//ptah:schema:field name="title" type="TEXT" not_null="true"	Title string} # The constraint came back with its name and its actions.

Sign off a plan

        
      

      
A plan saved, signed with an SSH key, and refused the moment one identifier in it changes. The reviewed plan is the plan that runs.


      

        

          sh · ptah-release
          
        
          
          
          
          
        
        

        

        
# Save the plan, so what is reviewed is what runs.$ ptah schema plan --schema-file schema.sql \    --db-url sqlite://app.db --name add-active-users \    --output plan.jsonPlanned schema changes:CREATE TABLE "users" (  "id" INTEGER PRIMARY KEY,  "email" TEXT NOT NULL,  "legacy_ref" TEXT);Plan saved to file://plan.json # Sign it. Ptah never reads the key; ssh-keygen does.$ ptah schema approve --plan plan.json --key ./release_keyApproved plan.jsonSignature: plan.json.sig$ ptah schema verify-approval --plan plan.jsonApproved by release@example.comPlan digest: cb74d5837d3efb8c1a8c93bd930fd0321d12abc5e13fd731ff129c43bf0bfc41 # Now change one identifier in the approved plan.$ sed -i 's/legacy_ref/legacy_id/g' plan.json$ ptah schema verify-approval --plan plan.jsonerror: approval does not verify against .ptah/allowed_signers: either the plan changed after it was approved, or it was signed by a key that file does not list # Exit 2. An edited plan is a plan nobody approved.
