驚きのないデータベースマイグレーション

Ptah（プタハ）は、目標スキーマと稼働中のデータベースを比較し、バージョン管理型マイグレーションを書くか、承認済みの計画を適用する。pgvector テーブルの再埋め込みのような、永続的な推論状態の移行も扱う。PostgreSQL、MySQL、MariaDB、SQLite ほか。オープンソース、MIT ライセンス、導入すべきツールチェーンはない。

$ curl -fsSL https://ptah.run/install.sh | sh

マイグレーションがデータベースに触れる前に、何をするのかを正確に知る。レビューの対象は計画であり、ドリフト検査がその結果を裏づける。

      

    

  


  

    

      

        
ふつうの一週間にやること、3 つ

        
実際のコマンドと、実際の出力。終了コードはどれでも同じ意味を持つ。0 は成功、1 は検査結果が否定的だったこと、2 は使い方か接続の失敗。

      

      

        

          

            
01 · プルリクエストを止める

            
スキーマがずれたとき、マイグレーションが危険なときに CI を落とす

          

          
$ ptah migrations lint --dir ./migrations \
    --dialect postgres
No lint findings.
$ ptah schema drift \
    --schema-file schema.sql \
    --db-url "$PTAH_DATABASE_URL"
No schema drift detected.

          
あるいは uses: stokaro/ptah-action@v1。計画をプルリクエストに投稿し、破壊的変更のチェック結果を書き込む。

        

        

          

            
02 · マイグレーションディレクトリを封じる

            
レビュー後にバイト列が変わったマイグレーションファイルを拒否する

          

          
$ ptah migrations hash --dir ./migrations
Wrote ./migrations/ptah.sum
2 migration file(s) hashed
$ ptah migrations status \
    --db-url sqlite://app.db \
    --migrations-dir ./migrations
Current Version: 1700000000
Total Migrations: 1
Applied Migrations: 1
Pending Migrations: 0

          
ptah.sum はファイルごとにチェックサムを記録する。以降のコマンドは、何かを実行する前にそれを検証する。

        

        

          

            
03 · 埋め込みモデルを変える

            
pgvector テーブルを再埋め込みし、検証が済むまで古いベクトルを残す

          

          
ptah inference plan
ptah inference prepare
ptah inference backfill
ptah inference catchup
ptah inference index
ptah inference verify
ptah inference cutover
ptah inference rollback · retire

          
Ptah は、稼働中の世代の隣に新しい世代を作り、OpenAI 互換の埋め込みエンドポイントを呼び、検証し、指示があった時点でクエリを切り替える。ベクトルそのものを Ptah が作ることはない。

        

      

    

  


  

    

      

        
いま持っているスキーマがそのまま使える

        
どの入力元も、計画を立てる前に同じ内部スキーマへ解析される。--schema-file と --root-dir は何度でも指定でき、混ぜてもよい。統合した結果が目標スキーマになる。独自形式は必要ない。

        

          
--schema-file
SQL、YAML、HCL、DBML

          
--root-dir
アノテーション付きの Go 構造体

          
--schema-cmd
SQL、HCL、YAML を出力する任意のプログラム — ORM のエクスポーターなど

          
--db-url
稼働中のデータベース。ptah introspect で Go のモデルとして読み戻せる

        

      

      
schema.sql · models/*.go · live db
        │
        ↓
      ptah  validate → plan → lint → apply → drift
        │
        ↓
     database
