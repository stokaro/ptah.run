コミュニティ

Ptah（プタハ）は GitHub 上で公開して開発している。質問、アイデア、バグ報告、貢献は誰からでも歓迎する。データベースや Go の経験は問わない。

参加は 行動規範に従う。やりとりは英語で行われている。日本語での投稿も読まれるが、返事は英語になることが多い。

質問する

ptah、ptah-compat、Go ライブラリで何かをする方法を尋ねる場所、まだ具体的な機能要望になっていないアイデアを出す場所、Ptah で作ったものを見せる場所が GitHub Discussions である。読むのは誰でもでき、投稿には GitHub アカウントが要る。

よく出る質問には FAQ と トラブルシューティング が答えているので、まず ドキュメントを検索してほしい。返信で解決したら、それを回答として選んでおくと次の読者が見つけやすい。

Q&A で質問する → Discussions を見る

バグを報告する

バグと機能要望は Issue トラッカーへ。そこで一つずつラベルと担当者が付く。フォームが尋ねるのは、報告を扱えるものにする情報である。実行したコマンド、ptah version の出力、エンジンとサーバーのバージョン、そして問題を再現する最小の入力。どちらのバイナリを実行したかも書いてほしい。ptah と ptah-compat は意図的に異なるコマンド体系を提供している。

Kubernetes オペレーターの問題は stokaro/ptah-operator へ、このウェブサイトの問題は stokaro/ptah.run へ。

Issue を作成する → 既存の Issue を検索する

脆弱性を報告する

セキュリティ上の問題は、Issue や Discussions ではなく GitHub のアドバイザリーフォームから非公開で報告してほしい。メンテナーがアドバイザリーを公開するまで、報告を見るのは報告者とメンテナーだけである。

貢献する

コードは助け方の一つにすぎない。縮小した再現手順、実サーバーに対する測定、間違ったページの訂正、Discussions での回答も同じだけ助けになる。変更の提案と、それが通すべき検査については CONTRIBUTING.md に、CI のゲートが強制する作業規則については AGENTS.md に書かれている。

挙動を変える変更は、先に Issue を立ててほしい。差分ができる前に設計を決めるためである。

リポジトリ

Ptah は stokaro organization 配下の複数のリポジトリからなる。それぞれが自分の Issue とプルリクエストを受け付ける。

stokaro/ptah
ptah、ptah-compat、ptah-ls のバイナリ、Go ライブラリ、そして docs.ptah.run のドキュメント。
stokaro/ptah-operator
Kubernetes オペレーター。ガイドは operator.ptah.run。
stokaro/ptah-action
GitHub Action。マイグレーションの計画、lint、プルリクエストへのコメント、破壊的変更のチェック。
stokaro/ptah-testkit
Ptah を組み込むプロジェクト向けのテストヘルパー。ptah.run/testkit としてインポートする。
stokaro/ptah-sandbox
プレイグラウンド。CLI を WebAssembly にコンパイルし、ブラウザ内の実際の SQLite に対して動かす。
stokaro/homebrew-ptah
brew install stokaro/ptah/ptah の裏にある Homebrew タップ。
stokaro/ptah.run
このウェブサイト。

商用サポート

商用の問い合わせはメールで受け付けている。アドレスは FAQ にある。バグ報告と機能要望は、公開されたままになる Issue トラッカーに置いてほしい。
